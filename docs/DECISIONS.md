# DECISIONS.md

Decisions taken for the Lenz Rescue rebuild, with the reason. If one of these is reversed, update the
entry rather than deleting it, and update the file it affects.

1. **Concept is Night Drive.** Amber equals the problem, cool white equals the solution, and the page
   gets visually clearer as you scroll. Chosen over an optical or a workshop direction because the
   product is literally light, and because it gives every colour and motion decision a rule to obey
   instead of a taste call. DESIGN.md section 1.

2. **The client's `#07170f` is kept.** It becomes `--pine` and carries the section bands and the
   scrolled header. A darker `--night` sits beneath it as the page ground so there is somewhere for
   depth to come from. We did not throw away the one brand decision they had already made.

3. **Six colours, three fonts, three radii, one spacing scale.** Hard limits written into DESIGN.md
   section 7 as a ban list. The failure mode on a build like this is not a bad choice, it is forty
   small unmanaged choices.

4. **The owner story is told once.** The current site tells it in two near-identical sections, "Our
   story" and "About", which reads as padding. It now appears once on the home page and once more at
   length on `/about`, and nowhere else. Tone shifts from "help a kid out" to "young tradesman who
   does the fourth step every time", because the apologetic version undercuts the price.

5. **The story is removed entirely from `/dealer-and-auction`.** A dealership buying twenty units
   wants turnaround and consistency, not charm. Different audience, different page, different voice.

6. **Single page becomes twelve routes, including four location pages.** The current site cannot rank
   for "headlight restoration Antioch" because there is no page about it. Location pages are written
   individually, not generated by city-name substitution, because near-duplicate location pages are
   worse than none.

7. **The Venmo icon and the unlinked Square icon come out of the footer.** Payment logos in a footer
   read as a market stall. Payment methods are stated in words on the FAQ instead, once the client
   confirms them. The dangling `#process` link and the empty-label "Z" icon go too.

8. **3D is one fragment shader, not a model.** The entire WebGL budget is a fullscreen plane running
   the beam shader in MOTION.md section 7. No GLTF, no loaders, no HDRI, no post-processing. A real
   3D headlight would need a model nobody has, would cost megabytes, and would look worse than the
   shader on a phone.

9. **Shader fallback, if the budget is missed.** If three.js pushes the home route past 230KB
   gzipped, replace it with a 2D canvas radial-gradient beam following the same lerped pointer. Do
   not substitute a different 3D library. The visual idea survives, the weight does not.

10. **Redirects to add in `next.config.ts`.** The old site is one page with anchors, so most of these
    are defensive against links already in the wild. All permanent.

    | From | To |
    |---|---|
    | `/index.html` | `/` |
    | `/assets/:path*` | `/media/:path*` |
    | `/#services` | `/headlight-restoration` |
    | `/#results` | `/gallery` |
    | `/#guide` | `/vehicle-guide` |
    | `/#about` | `/about` |
    | `/#contact` | `/contact` |
    | `/#request` | `/contact` |
    | `/#process` | `/headlight-restoration` |

    Anchor redirects cannot be done server side, since the fragment never reaches the server. Handle
    these with a small client-side check in the root layout that reads `location.hash` on first load
    and routes accordingly, then clears the hash.

11. **Reviews are built but not shipped empty.** The current site refers to reviews it does not show,
    which actively costs trust. The section exists in code behind a `ReviewPlaceholder` state and is
    kept out of the page order until the client supplies the Google profile URL, the rating, the
    count and three review texts. An empty reviews section is worse than no reviews section.

12. **The guarantee needs written terms before launch.** "3 year guarantee" appears three times on
    the current site with no terms anywhere. It now appears twice, with terms. An unqualified
    multi-year guarantee on a cosmetic restoration is a liability, not a selling point.

13. **Every image is treated, not shown raw.** The client's photos are phone photos taken in mixed
    light. The filter stack and the oxide and xenon tints in DESIGN.md section 5 are what make an
    inconsistent set read as a deliberate before and after system. Without that treatment the gallery
    will look like a Facebook album regardless of how good the rest of the site is.

14. **Placeholders ship visibly during the build.** `PlaceholderFrame` shows the expected filename
    and ratio, and `TODO(owner)` items render as small chips. The client sees exactly what is still
    missing at review time instead of discovering it at launch. Both are removed in Prompt 6.

15. **Reduced motion is a build requirement, not a nicety.** Spelled out per component in MOTION.md
    section 2 and checked in QA. A site whose whole concept is motion has to be usable without it.
